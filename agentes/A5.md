# A5 — Correo asíncrono exactamente una captura local

**Dependencia:** A2 confirmado con outbox insertado transaccionalmente, A3 para mostrar failed. **Propiedad:** `apps/api/src/emails/`, worker y tests E. **No usa SMTP como transporte obligatorio.**

## Leer
`CONTRATOS_Y_MODELO.md` «Algoritmos canónicos de estados y correo»; matriz R29–R33, suite E. Esta decisión sustituye al worker SMTP original de P2.

## Entregar
1. Outbox con `dedup_key UNIQUE` y `booking_id` único para el evento `booking-confirmed`, `status=pending|sent|failed`, `attempts`, `next_attempt_at`, `last_error`, `payload` y fecha.
2. Worker `FOR UPDATE SKIP LOCKED`, sin esperar envío desde `/confirm`. Proceso separado `pnpm worker` o dev inline sin duplicar consumidores. Una transacción corta por lote/evento.
3. Sink canónico `captured_emails`: almacena `booking_id UNIQUE`, `dedup_key UNIQUE`, destinatario, asunto, cuerpo, captured_at. En caso de éxito, insertar captura **y** cambiar outbox a sent en el mismo commit. Si cae antes del COMMIT, ambos se revierten; tras el COMMIT no se vuelve a procesar.
4. Intento inicial más **hasta cinco reintentos** (seis fallos máximos) con esperas 1, 2, 4, 8, 16 min, fecha duradera; si se agotan, `failed` visible en admin. Test con reloj simulado, no sleep real.
5. Error inyectable solo en entorno local/test a nivel de transporte, antes de insertar captura, para demostrar retries/failure sin exponer endpoint inseguro.
6. API admin `GET /api/admin/emails` (A3 colabora) para ver correos capturados y `failed`, incl. attempts y last_error.
7. **Opcional**: transporte SMTP de demostración a Mailpit. Si se implementa, separar semántica at-least-once y documentar ventana de duplicación ante caída tras ACK y antes de COMMIT. NO presentarlo como garantía «un solo envío externo».

## Pruebas obligatorias
- Worker apagado: confirmar retorna sin esperar, queda un evento pending.
- Un evento correcto produce **una sola captura**; dos workers concurrentes o crashes simulados antes/después del COMMIT no crean duplicados.
- Cinco fallos con backoff seguidos del sexto fallo => failed, attempts=6, visible admin; sin duplicar salida por replay de confirm.
- Prueba de `UNIQUE (booking_id)` tanto en outbox como captura, con PG real. Si no se puede simular caída de proceso, al menos test transacciones rollback/commit.

## Aceptación
A5 entrega prueba observable del límite de garantía; mailpit opcional no bloquea la aceptación. Commits separados para worker/sink/retries/admin/tests.
