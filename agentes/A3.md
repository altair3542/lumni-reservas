# A3 — Autenticación y administración de reservas

**Dependencia:** A0 y A2. **Propiedad:** `apps/api/src/auth`, `apps/api/src/admin`, tests S/U. A0 deja contrato inicial de sesión; no cambiarlo unilateralmente.

## Leer
`CONTRATOS_Y_MODELO.md` Endpoints y seguridad; matriz R22–R26, R40 y suite U/S.

## Entregar
- Login y logout con usuario/contraseña sembrados; `password_hash`, cookie HttpOnly SameSite=Lax con expiración, token opaco o equivalente seguro. Sin contraseña ni hash en `/api/me`. `Secure` en HTTPS.
- `requireAuth`, `requireRole`, `requireOwner`; recursos de otro cliente se tratan como inexistentes 404.
- `GET /api/admin/bookings`: paginación real por DB (page≥1, pageSize limitado), orden estable, filtro combinado status+roomId, total de resultados filtrados.
- `GET /api/admin/bookings/:id`: desglose, estado outbox (pending/sent/failed, attempts, lastError) y motivo de cancelación.
- `POST /api/admin/bookings/:id/cancel`: motivo no vacío y `expectedVersion`, solo desde confirmed; validar en backend. `POST .../complete` solo si existe política aprobada de completado y condición temporal.
- `GET /api/admin/emails` y detalle para inspeccionar capturas locales y eventos fallidos; no exponer a cliente.

## Pruebas exigidas
Cliente no entra a admin por HTTP aunque manipule frontend; rol alterado en payload no cambia permisos. Admin pagina sin perder filas, filtra sala+status juntos. Cancelación vacía 422, repetición/inválida 409, motivo conservado, recálculo prohibido. Sesión inválida/caducada 401, otro dueño 404.

## Aceptación
API admin y permisos demostrados con Supertest y BD real; no existe acceso anónimo a capturas ni a datos ajenos. Commits pequeños auth / listados / transiciones / tests.
