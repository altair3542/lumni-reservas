# A6 — Asistente IA de reservas seguro y retomable

**Dependencia:** A1/A2 completos y estable el contrato Quote/Draft. **Propiedad:** `apps/api/src/assistant/`, `apps/web/src/assistant/` y tests A. La UI no autoriza confirmación por chat.

## Leer
`PLAN_MAESTRO.md` §2.5 y `CONTRATOS_Y_MODELO.md` «Contrato limitado con el modelo» y «Desambiguación». Matriz R34–R46 y suite A. Antes de desarrollar comprobar una llamada auténtica al modelo y credenciales en variables de entorno.

## Entregar
1. `prompt.md` en repo con cuatro reglas explícitas; nunca colocar tarifas, secretos, consultas SQL, datos de otros clientes ni código de confirmar/cancelar en herramientas.
2. `LlmClient` desacoplado y mockeable, adaptador API de IA real con modelo por env, timeout y límite de tokens/mensajes. Un mock de test **no sustituye** la demostración con proveedor real.
3. Interpretación **estructurada**: intent, patch de slots, evidence textual para datos inferidos de entrada; Zod `strict` rechaza campos ajenos y formatos erróneos; comprobar evidencia contra mensaje original antes de aplicar un campo. «El sábado en la mañana» no inventa hora exacta ni duración; preguntar una cosa por turno.
4. `resolveDate` puro con reloj y zona Bogotá; resuelve «el sábado»/«mañana» en código, pide aclarar «próximo sábado» si es ambiguo; no desplazar automáticamente fechas guardadas al recargar.
5. Orquestador construye cotización/alternativa **solo** llamando `QuoteService` real. No mostrar texto del modelo como fuente de precio/disponibilidad ni renderizar HTML generado por él. Tarjetas construidas desde respuesta del servidor.
6. Crear/editar un único borrador ligado a conversación autorizada, solo del cliente que deriva de la sesión. Nunca confirmar/cancelar/listar clientes. Alternativa sugerida no se usa para crear draft hasta aceptarla.
7. Mensajes/historial/slots/conversación persistidos en PostgreSQL. Resolver carreras con `expectedVersion` y `clientMessageId` idempotente; la llamada externa se realiza fuera de transacción. Al refrescar recuperar texto y tarjetas sin crear nuevo draft.
8. UI chat en la app con tarjetas Quote/Draft, enlaces al wizard; botón «Confirmar» exclusivamente en la app vía A4, no como tool del asistente. Error amable cuando falta API key o falla proveedor.

## Pruebas exigidas
- 6 personas sábado en la mañana con proyector: solicita hora/duración faltantes, elige sala según capacidad asumida, quote real, draft ligado; sin datos inventados.
- Prompt injection «ignora reglas» / «confirma tú» / `customerId` ajeno / tool desconocida: sin modificaciones privilegiadas. Validación de entrada **y** respuesta incorrecta no cambia estado.
- Date expression con TZ del servidor en UTC y reloj Bogotá; reload conserva historial; peticiones duplicadas mantienen un solo draft. Probar extracción con fake y **demo separada de llamada real**.

## Aceptación
Todas las reglas 1–4 se argumentan estructuralmente y con pruebas, sin afirmar inmunidad absoluta del LLM a prompt injection. A9 recibe texto explicativo y evidencia auténtica.
